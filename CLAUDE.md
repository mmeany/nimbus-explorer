# Nimbus Explorer: project guide

Explorer-style desktop app that works with AWS: S3, Parameter Store, SQS, SNS, DynamoDB,
RDS, ECS, Lambda, CloudWatch Logs and Secrets Manager (see the services plan below). Works with emulators (LocalStack,
MinIO, moto). (Formerly "S3 Explorer", then "AWS Explorer"; the bundle identifier
`dev.example.s3explorer` is deliberately unchanged so settings persist.) MIT licensed. Experimental project; code is generated by Claude to
specs from the owner.

**Naming:** Amazon's trademark guidelines don't allow AWS marks in a product's
name, so keep them out of the product, package and repo names. Plain-text factual
references ("works with Amazon Web Services") are fine; no AWS logos, and never
imply affiliation.

## Architecture decisions (agreed; don't change without asking)

- **Shell:** Tauri 2. Uses the OS webview (WebView2 on Windows), so browser-engine
  security patches come from OS updates, not app rebuilds.
- **Frontend:** React + Vite + TypeScript. UI only: no secrets, no network calls.
- **Backend:** Rust. Does ALL AWS / HTTP calls.
- **AWS:** AWS SDK for Rust (`aws-config`, `aws-sdk-s3`). Credentials come only
  from the chosen AWS profile (`~/.aws/config` / `~/.aws/credentials`). SSO
  profiles rely on the user running `aws sso login` with the AWS CLI; the app
  detects expired tokens and shows that command.
- **TLS:** rustls + ring via `aws-smithy-http-client` (`rustls-ring`), with SDK
  default features off. No OpenSSL, no aws-lc (so Windows builds need only the
  MSVC Build Tools; no CMake/NASM). Keep it that way.
- **Custom endpoints:** a profile's `endpoint_url` (or AWS_ENDPOINT_URL) is honoured.
  A per-profile app override (endpoint + addressing style) lives in settings.
  Precedence: app override > SDK-resolved > our own profile parse. Custom
  endpoints default to path-style, a single client (no region discovery) and
  checksums only "when required".
- **Real AWS:** one client per bucket region; regions come from ListBuckets
  (`BucketRegion`, which requires `max_buckets`) or GetBucketLocation.
- **Settings:** JSON at `<app config dir>/settings.json` (Windows:
  `%APPDATA%\dev.example.s3explorer\`). Non-secret only. No keychain needed yet,
  because credentials come from profiles.
- **No SQLite/offline sync** in this app: S3 browsing is inherently online.
- **Theme:** System / Light / Dark, saved in settings (`theme`). System uses
  Tauri's window theme (`theme()` / `onThemeChanged`), live; if the OS can't
  report one, dark. The native title bar follows via `setTheme` (needs
  `core:window:allow-set-theme`). All CSS colours are tokens in `styles.css`
  with light AND dark values: never hard-code a colour in a rule.

## Dependency policy

Minimise shipped dependencies; every addition needs a reason.
- Shipped JS: `react`, `react-dom`, `@tauri-apps/api`. No UI kit, no icon
  library, no state library. Plain CSS.
- Rust: `tauri`, `tauri-plugin-dialog`, `serde`, `serde_json`
  (`preserve_order`, so YAML/JSON keys keep document order), `tokio`
  (sync, fs, io-util, rt, time), the AWS crates above plus `aws-sdk-ssm`,
  `aws-sdk-sqs`, `aws-sdk-sns`, `aws-sdk-dynamodb`, `aws-sdk-rds`,
  `aws-sdk-rdsdata`, `aws-sdk-cloudwatchlogs`, `aws-sdk-lambda`, `aws-sdk-ecs` and `aws-sdk-secretsmanager` (default features off) (+ `aws-smithy-types` for base64, `aws-smithy-runtime-api` (already part of
  the SDK) to fetch Lambda code download links with the SDK's own HTTP client,
  `aws-credential-types` for credential expiry), `yaml-rust2` (no default
  features) for YAML previews.
- Native dialogs are opened from Rust commands (`pick_upload_files`,
  `pick_folder`, `pick_save_file`), so there is no JS dialog plugin and no
  dialog permissions in capabilities.
  Disable unneeded crate features. Run `cargo audit` before releases.
- AWS SDK features `sigv4a` (aws-sdk-s3) and `credentials-login` (aws-config)
  are deliberately off: they pull in `crypto-bigint` 0.5 (RUSTSEC-2026-0387,
  no fixed release in the SDK yet). Consequences: no S3 Multi-Region Access
  Points, no profiles created with `aws login`. Re-check before turning
  either back on.
- Build tools (vite, typescript, tauri-cli) are not shipped; CVEs there don't
  require app rebuilds.

## Code layout & rules

Shell + services (since 0.2):
```
src/App.tsx                    shell: profile/connection, theme, layout, history,
                               shared dialogs; composes the service controllers
src/shell/places.ts            Place = Home | per-service location; SERVICES registry,
                               crumbs, parentPlace, placeUri, samePlace
src/shell/shell.ts             Shell (what services may ask of the app: navigate, ask,
                               askName, showError/Flash, setWorking, openMenu, copyText,
                               openTransfers) and ServiceUi (tree, content, commands,
                               status, busy, refresh, dialogs, onTransferFinished)
src/services/<svc>/use<Svc>Service.tsx  one controller hook per service; always
                               mounted (its tree branch shows even when inactive)
src/components/TreeRow.tsx     generic tree row (+ TreeNote) for every service branch
src/components/CommandButton.tsx  command-bar button / separator
src/api/core.ts                `call` (invoke wrapper), AppError, profile/settings types;
                               each service has src/api/<svc>.ts built on it
src-tauri/src/commands/mod.rs  AppState + app-level commands (profiles, settings,
                               connect, dialogs, transfer cancel, parse_yaml)
src-tauri/src/commands/<svc>.rs  one module per service
```
Adding a service: extend `ServiceId`/`Place`/`SERVICES` and the place helpers,
write `api/<svc>.ts`, `services/<svc>/use<Svc>Service.tsx`, register it in
App's `services` map and SERVICE_ICONS, add `commands/<svc>.rs` and register its
commands in lib.rs.

Earlier layout (S3 internals):
```
src/api/s3.ts           S3 + app-level typed wrappers (re-exports core)
src/api/window.ts       OS/window integration (theme). src/api/ is the only place
                        touching Tauri APIs, so the UI also runs in a plain browser
src/state/theme.ts      useTheme(): resolves preference, sets <html data-theme>
src/state/folder.ts     useFolderPage(): one ListObjectsV2 page at a time (page size, search
                        prefix, recursive), tokens + visited pages cached per query
src/state/tree.ts       useFolderTree(): lazy nodes keyed bucket+prefix; reveal() on navigate;
                        completed listings feed children via setChildren()
src/format.ts           size/date formatting
src/viewers/csv.ts      RFC 4180 CSV parser, delimiter detection, header names
src/viewers/markdown.tsx  own Markdown renderer → React elements (no HTML strings)
src/state/transfers.ts  useTransfers(): live transfer list from `transfer` events
src/components/         + TransfersPanel, ContextMenu, ConfirmDialog (generic),
                        PromptDialog (name entry with validation), PreviewDialog,
                        TextPreview (per-type view modes), DataTree (folding),
                        CsvView, ShareDialog, PropertiesDialog
src/state/navigation.ts Location model (bucket + prefix), history, breadcrumbs
src/components/         Toolbar, FolderTree, FileList (generic details view),
                        ErrorPanel, ConnectionDialog, StatusBar, Icons
src-tauri/src/commands.rs  thin Tauri commands (the whole UI-facing surface)
src-tauri/src/s3.rs        Connection: client building, S3 operations
src-tauri/src/profiles.rs  profile discovery (names, region, endpoint_url, sso_session)
src-tauri/src/settings.rs  JSON settings store
src-tauri/src/sync.rs      sync planner/runner (see step 6)
src-tauri/src/yaml.rs      YAML → JSON via yaml-rust2's event parser with a node
                           budget (the stock loader expands aliases eagerly, so
                           "billion laughs" files could exhaust memory)
src-tauri/src/transfers.rs uploads/downloads: semaphore (3 at once), `transfer`
                           progress events (throttled), cancel flags, multipart,
                           path sanitising for downloads
src-tauri/src/error.rs     AppError {kind, message, detail} classification
```
- Commands return `Result<T, AppError>`; the UI switches on `kind`
  (`ssoExpired`, `noCredentials`, `unreachable`, `accessDenied`, `other`).
- Serde uses camelCase across the boundary. Tagged enums also need
  `rename_all_fields = "camelCase"` (see `Preview`).
- Keep commands thin; logic in modules.
- FileList is virtualised (fixed ROW_H = 22px, must match `.fl-row` CSS) so
  folders with tens of thousands of objects stay responsive.
- Folder marker objects (zero-byte `prefix/`) are hidden from file lists.
  Empty path segments (`a//b`) are valid and display as "(unnamed)".
- Downloads write to `<name>.s3x-part` and rename on completion; S3 key
  segments are sanitised (`safe_segment`) so keys can't escape the target
  folder or use names Windows rejects.
- Toolbar has three rows: profile/endpoint/theme; command bar; navigation +
  address bar.
- Classic Explorer UX: tree on the LEFT, details list on the right, status bar,
  Explorer keyboard shortcuts.

   show object count + size), Copy S3 URI, tree width remembered
   (localStorage), README with shortcuts.

5a. ✅ Rich previews: Markdown (Rendered/Source; links don't navigate, click
   copies the address; remote images shown as placeholders since CSP blocks
   them), CSV/TSV (Table/Tree/Text; header + delimiter options; tree = one
   collapsible record per row), JSON (Tree/Formatted/Raw), JSONL (Tree/Raw),

   (disabled > 20k nodes), collapse all, expand to level 1-4, 200 children
   per node then "Show more". Tree/formatted/rendered need the whole file
   (disabled for truncated >5 MB previews). View mode remembered per type.
6. ✅ Sync (like `aws s3 sync`), local folder <-> current S3 folder, either
   direction. Implemented in `src-tauri/src/sync.rs` (pure `compute_plan`,
   `plan`, `PlanStore` keeps the latest plan so "Run sync" executes exactly what
   was previewed, once) and `src/components/SyncDialog.tsx` (options
   remembered per S3 folder in localStorage). Deletes are listed first so
   they always appear in the 100-row summary; runs with deletes need a second
   confirming click; local deletes are permanent (not Recycle Bin).
   - Planner (Rust) lists both sides and decides per file: upload/download if
     missing or size differs or source is newer; skip otherwise. Optional
     "delete extras" (mirror), "size only" comparison, exclude patterns
     (`*`/`?`, own matcher, no new dependency).
   - Mimic the CLI's timestamps: after a download, set the local file's mtime
     to the S3 LastModified (std `File::set_modified`) so re-syncs are no-ops.
   - **Dry run option** (no changes made). The full comparison always runs, so
     totals (files + bytes to upload/download/delete, skipped) are exact. If
     more than 100 actions, the table lists only the first 100 and is clearly
     labelled as a summary ("showing 100 of N").
   - A preview is always shown before a real run executes; deletes require it.
   - Skip with a warning: keys that can't round-trip to local names
     (sanitised characters) and case-only collisions on Windows.
   - Execution reuses the transfer engine; deletes reuse step 4's bulk delete.
   - Later: S3 <-> S3 sync, saved sync pairs, optional content (ETag) compare.

## Commands

- `npm install`: first time
- `npm run tauri dev`: run the app with hot reload
- `npm run tauri build`: release build + installers (`src-tauri/target/release/bundle/`)
- `npm run build`: typecheck + build frontend only
- `cd src-tauri && cargo test`: unit tests
- `cd src-tauri && cargo check`: also run it (not just tests) before committing
  Rust changes. Tests enable tokio `macros` / `rt-multi-thread` (dev-dependency),
  the app doesn't, so `tokio::join!` / `select!` / `#[tokio::main]` compile in
  tests but break the release build.
- `cd src-tauri && cargo test -- --ignored --test-threads=1`: emulator tests;
  need an S3 emulator on `localhost:4566` (LocalStack or `moto_server -p 4566`)

## Services plan (agreed 2026-10-25; build in this order, stop after each phase)

App becomes **AWS Explorer** (since renamed Nimbus Explorer). Services appear as top-level tree nodes under the
profile: S3, Parameter Store, SQS, SNS, DynamoDB, Secrets Manager. Order:
Phase 0 → Parameter Store → SQS → DynamoDB → Secrets Manager → SNS. One commit per
numbered item. Checkpoint with the owner after each phase. Each service gets
`docs/<service>.md` (user guide) plus README and CLAUDE.md updates.

Cross-cutting decisions:
- **Regions:** toolbar region switcher (default = profile region, remembered per
  profile) for the regional services; S3 keeps per-bucket regions.
- **Read-only mode:** lock that is on for every new connection (app start,
  profile switch; changed 2026-11-01, no longer remembered); disables writes in the UI AND is enforced in the
  backend (write commands refuse). Applies to S3 too. Destructive actions
  still confirm; deleting a queue / table or force-deleting a secret needs a
  typed name confirmation.
- **Secrets:** SecureString / secret values masked; decrypted only on explicit
  Reveal or Copy; never cached or logged. Exports include decrypted values only
  if an off-by-default option is ticked (with warning).
- **Values that are JSON/YAML:** shown with the DataTree; editors validate JSON
  and can pretty-print.
- **Crates:** aws-sdk-ssm, aws-sdk-sqs, aws-sdk-dynamodb, aws-sdk-secretsmanager
  (default features off, same rustls+ring client). No new JS packages planned.
- **Tests:** emulator tests (moto/LocalStack) per operation where supported.
